РЕВЬЮ PIXEL-RUNNER — ФРОНТЕНД
======================================================================
Замечания по клиентской части: React, игровой движок (canvas), UX,
доступность, производительность рендера. По приоритету.


----------------------------------------------------------------------
ВЫСОКИЙ ПРИОРИТЕТ
----------------------------------------------------------------------

- Нет персистентности сессии (src/app/page.tsx:38).
  Всё состояние (screen, character, session) живёт только в useState. Reload /
  кнопка «назад» / случайное обновление стирает sessionId и прогресс и кидает на
  стартовый экран. В localStorage/cookie ничего не пишется.
  Фикс: сохранять sessionId (и текущий экран) в localStorage, восстанавливать при
  загрузке; подтянуть актуальное состояние игрока с сервера по sessionId.

- updateObstacles каждый кадр пересоздаёт весь массив препятствий и объекты
  hitbox (src/game/update.ts:49).
  .map + .filter + .concat на горячем пути 60 fps → лишний мусор и нагрузка на GC.
  Фикс: мутация на месте / пул объектов, а не пересборка массива каждый кадр.

- Тяжёлые PNG раздаются сырыми через <img>, next/image не используется
  (next.config.ts пустой; примеры <img> в src/screens/Form.tsx, src/screens/Game.tsx).
  Оптимизация изображений не настроена.
  Фикс: next/image или предварительная оптимизация ассетов (сжатие, спрайт-атласы).

- Модалка краша показывается оптимистично (src/screens/Game.tsx:264).
  setEndResult(result) вызывается до await updateGame(), а тело модалки читает
  серверные счётчики (attemptsLeft/bestDiscount). Если запрос упал — попытки не
  откатываются.
  Фикс: открывать модалку в success-ветке, после applySessionUpdate.

- Модалка без a11y (src/components/Modal.tsx:99).
  Нет role="dialog", aria-modal, focus-trap и начального фокуса — фокус остаётся
  на фоне под оверлеем.
  Фикс: role="dialog" aria-modal="true", перевод фокуса в модалку, trap, возврат
  фокуса при закрытии.


----------------------------------------------------------------------
СРЕДНИЙ ПРИОРИТЕТ
----------------------------------------------------------------------

- Весь модуль src/game/state.ts — мёртвый код (src/game/state.ts:20).
  createInitialState/buildObstacles нигде не импортируются (заменены update.ts).
  Тянут за собой OBSTACLE_LAYOUT/INITIAL_BARRIER_X из config.ts.
  Фикс: удалить state.ts и неиспользуемые экспорты config.ts.

- Экран completion заведён в тип Screen и есть компонент, но никогда не рендерится
  (src/lib/screens.ts:1, src/screens/Completion.tsx).

- Canvas-игра недоступна для скринридеров (src/screens/Game.tsx:997).
  Нет label на canvas, обновления HUD (пробег/скидка) не озвучиваются AT.
  Фикс: aria-label на canvas, aria-live для ключевых значений HUD.

- Нет viewport meta / viewport export (src/app/layout.tsx:17).
  Для mobile-first проекта масштабирование на мобилке не определено.
  Фикс: export const viewport = { width: 'device-width', initialScale: 1 }.

- updateField валидирует по устаревшему снапшоту values (src/screens/Form.tsx:43).
  setValues использует функциональный апдейт (prev), а пересчёт ошибки читает
  внешний values. Для одиночных правок работает, но хрупко.
  Фикс: считать ошибку от свежего состояния (в функциональном апдейте или useEffect
  по values).

- navigator.clipboard без фолбэка (src/components/CopyButton.tsx:59).
  В небезопасном контексте (http) или при отказе в разрешении copyToClipboard
  молча возвращает false — кнопка «Забрать скидку» не сработает без обратной связи.
  Фикс: фолбэк (execCommand/выделение) и сообщение об ошибке пользователю.

- getDifficulty(distance) вызывается, результат выбрасывается (src/game/update.ts:63).
  Путь роста сложности через этот вызов мёртв (сложность по факту задаётся через
  minKm/maxKm шаблонов). Убрать вызов.

- Ссылка на политику конфиденциальности без href (src/screens/Form.tsx:266).
  <a class="underline">политикой конфиденциальности</a> — не кликабельна и не
  фокусируется с клавиатуры. Добавить href.

- Шрифты Press_Start_2P/Handjet/Onest инициализируются в каждом компоненте заново
  (src/app/page.tsx:15, layout.tsx, Game.tsx, Modal.tsx, Input.tsx и др.).
  Фикс: один общий модуль с инстансами шрифтов.


----------------------------------------------------------------------
НИЗКИЙ ПРИОРИТЕТ
----------------------------------------------------------------------

- pickTemplate может вернуть undefined через eligible[...-1]! при пустом eligible
  (src/game/generator.ts:35) → падение на template.items в generateChunk. Сейчас
  замаскировано шаблонами с minKm:0. Обработать пустой случай явно.

- При провале валидации чанк молча возвращается пустым (src/game/generator.ts:94)
  → длинный пустой участок трассы вместо ретрая другого шаблона. Валидировать
  шаблоны на этапе сборки/тестов; в рантайме ретраить.

- finish_car с хитбоксом 0×0 (src/game/update.ts:95) — «никогда не сталкивается»
  закодировано вырожденным хитбоксом. Лучше явный флаг collidable: false.

- Магическое число mobileFinishCarOffsetX = 70 без пояснения (src/game/update.ts:86).

- isColliding сканирует все препятствия каждый кадр без раннего выхода + аллокация
  замыкания в forEach (src/game/collision.ts:16). Ранний return при первом
  пересечении, обычный for-цикл.

- getDiscount пересчитывается каждый кадр внутри setDistanceHud
  (src/screens/Game.tsx:243), сканируя DISCOUNT_TIERS. Обновлять скидку только при
  смене тира.

- obstacles.concat внутри while-цикла спавна чанков (src/game/update.ts:75)
  аллоцирует новый массив на каждый заспавненный чанк.

- Шаблон чанка с пустым id дублирует «konus затем hole» (src/game/chunk-templates.ts:67).

- Мёртвое/лишнее: spawnChunk (src/game/generator.ts:99), проброшенный isReturning,
  который ни на что не влияет (src/lib/api-client.ts:14, src/app/page.tsx).

- config.ts дублирует часть layout-констант, которые заново объявлены в mobile.ts;
  часть — мёртвая (src/game/config.ts:16).
